MobiMon 해커톤 데모 촬영 시나리오
================================
목표: 약 3분. 문제 → 차량 상태를 표현하는 친구 → AI 질문 → 보상/꾸미기 → 주차 안전.
녹화: Android Studio의 에뮬레이터 녹화 기능. 내레이션은 후시 녹음 권장.
아래 타임코드는 편집본 기준이다. 인증/응답/자동화 조작 시간까지 정확히 3분인 실행은 아니다.

원안에서 바꾼 점
----------------
1. "AAOS에 완벽하게 통합" 대신 "AAOS 에뮬레이터에서 시연"으로 표현한다.
   실차 VSS, OEM 런처, 백그라운드 관찰은 검증 완료로 설명하지 않는다.
2. Car Data 값이 이 앱의 Debug VSS에 연결된 것으로 가정하지 않는다.
   앱의 Debugger에서 배터리 값을 바꾸고 "차량 신호 시뮬레이션" 자막을 붙인다.
3. 로그인 성공을 연출하지 않는다. 실제 GitHub 승인을 기다린다.
   GitHub 계정 인증과 Copilot 대화 가능 여부는 따로 확인한다.
   기기 코드는 화면에 발급된 값을 사용한다. "8자리 알파벳"이라고 단정하지 않는다.
4. 답변은 화면 텍스트로 보여준다. 캐릭터의 음성 답변은 현재 구현 범위로 설명하지 않는다.
5. 매뉴얼은 Debug에 포함된 2027 한국형 IONIQ 5 자료다. 다른 차종/연식으로 일반화하지 않는다.
6. 퀘스트는 조건 시뮬레이션 → 실제 화면의 보상 수령 → 구매 → 적용 순서로 보여준다.
   디버거의 포인트 추가나 일괄 지급을 정상적인 주행 보상처럼 촬영하지 않는다.
7. 주차 해제 시 상호작용 제한과 캐릭터 퇴장 애니메이션을 구분한다.
   애니메이션이 존재하므로 "주행 순간 완전히 사라진다"고 단정하지 않는다.

촬영 전 준비
------------
- AAOS 에뮬레이터를 Android Studio에서 실행하고 Debug APK를 설치한다.
  패키지는 com.monsters.mobimon.demo. Release 패키지는 이 도구가 조작하지 않는다.
- 2560x1440 가로 화면과 기본 글자 크기를 사용한다. 메뉴만 이 배치의 검증한 좌표를 사용하고,
  일반 화면은 문구를 찾아 조작하고, 오버레이 TEST 버튼은 실제 창 위치를 조회한다.
  다른 해상도에서는 사전 확인이 중단된다.
  메뉴 구성이나 문구가 바뀐 빌드에서는 중단될 수 있다. 먼저 장면별 리허설을 한다.
- Windows에서는 Git Bash와 Python 3를 사용한다. adb는 PATH 또는 Android SDK에서 찾는다.
  필요하면 ADB 환경변수에 adb 실행 파일의 경로를 지정한다.
- 원하는 친구를 먼저 선택한다. 기본 스크립트는 모비 고글을 선택한다.
  루나로 촬영하면 --item '루나 선글라스'를 지정한다. 친구는 자동 구매하지 않는다.
- 보상 장면의 "놓지마 생명줄!" 퀘스트는 아직 보상을 받지 않은 상태여야 한다.
  보상 수령 후 아이템 가격(현재 300 P)을 지불할 수 있도록 미리 잔액을 확인한다.
  아이템이 이미 착용 중이면 다른 미착용 아이템을 고른다.
  보유 아이템이면 구매 장면 대신 적용 장면을 촬영한다. 화면과 내레이션을 맞춘다.
- 차량 상태 카드에 배터리 잔량이 표시되도록 준비한다.
  다른 경고가 없어야 낮은 배터리와 회복 표정이 잘 보인다.
  배터리의 수동 해석 고정값은 도구가 '자동'으로 해제한다. 다른 항목의 고정값은 직접 확인한다.
- 설정에서 Debugger를 켜고 창을 최소화한다. X로 닫았다면 Debugger를 껐다 켠다.
  도구는 P/속도 0을 준비하고 배터리를 15 → 80으로 변경한다. 이전 값은 자동 복원하지 않는다.
  입력 결과는 Debug 시뮬레이터 설정 파일을 읽어 확인한다. 파일/DB를 직접 수정하지 않는다.
- 설정의 차량 홈 캐릭터를 직접 켜고 "다른 앱 위에 표시" 권한을 허용한다.
  움직임 줄이기는 끈다. 홈으로 나갔을 때 캐릭터와 TEST P → D 버튼이 보이는지 확인한다.
- GitHub OAuth public client ID가 설정된 Debug 빌드를 사용한다.
  저장소 빌드 설정: mobimon.githubClientId 또는 MOBIMON_GITHUB_CLIENT_ID.
  client secret은 필요 없다. 로그인과 실제 Copilot 대화를 미리 시험한다.
- 첫 연결 장면을 찍으려면 앱의 연결 해제를 직접 수행한다. 스크립트는 자동 로그아웃하지 않는다.
  이미 연결되어 있다면 기존 계정 상태를 보여주고 QR 발급 단계는 건너뛴다.
- 스마트폰에서 화면에 표시되는 GitHub 기기 인증 주소를 열고 로그인해 둔다.
  휴대폰 승인은 직접 한다. 승인 중에는 앱을 백그라운드로 보내거나 주차 상태를 바꾸지 않는다.
- 대화 입력란은 비워 둔다. 스크립트는 기존 초안을 지우지 않는다.
  질문 1건은 실제 Copilot에 전송된다. 계정 사용량이 적용된다.

실행
----
저장소 루트 D:/Hackathon/RIVO에서 Git Bash로 실행:

  bash scripts/demo/record-demo.sh --check
  bash scripts/demo/record-demo.sh --step

루나 버전:

  bash scripts/demo/record-demo.sh --step --item '루나 선글라스'

여러 기기 중 하나 선택:

  bash scripts/demo/record-demo.sh --serial emulator-5554 --step

장면별 재촬영:

  bash scripts/demo/record-demo.sh --scene vehicle
  bash scripts/demo/record-demo.sh --scene auth
  bash scripts/demo/record-demo.sh --scene chat
  bash scripts/demo/record-demo.sh --scene quest --item '루나 선글라스'
  bash scripts/demo/record-demo.sh --scene overlay

도구가 "준비 완료"를 표시하면 Android Studio에서 녹화를 시작하고 터미널에서 Enter.
--step은 각 장면 직전에도 기다린다. 기본 실행은 장면 사이에 자동 진행한다.
--pace 0.5는 관찰용 정지 시간을 절반으로 줄인다. 인증/응답 속도를 높이지 않는다.
--auth-timeout 300은 실제 기기 승인 대기 한도를 300초로 설정한다.
record-demo.sh와 record_demo.py는 같은 폴더에 둔다. 별도 Python 패키지는 필요 없다.

사람이 진행하는 부분
-------------------
녹화 시작/정지, 스마트폰 GitHub 승인, 새 AI 답변과 출처의 육안 확인은 수동이다.
화면 이동, 배터리 변경, 퀘스트 조건 설정/수령, 아이템 구매/적용, TEST P/D 조작은 자동이다.
AI 답변이 도착하면 이번 질문의 답변과 출처가 실제로 있는지 확인한 뒤 Enter를 누른다.
오류/출처 누락이면 Ctrl+C로 중단한다. 오래된 답변을 새 성공 장면으로 사용하지 않는다.

Scene 1. 주차 중의 새로운 동반자 [0:00–0:20]
-------------------------------------------
화면: 앱 홈. 캐릭터 표정과 "주차 확인됨" 배지를 3초 이상 보여준다.
자막: "MobiMon | 주차 시간의 새로운 동반자"
      "AAOS 에뮬레이터 · 차량 신호 시뮬레이션"
내레이션:
"차 안에서 잠시 쉬는 시간, 차량 정보도 조금 더 친근하게 만날 수 없을까요?
 MobiMon은 주차 중 차량 상태를 함께 살펴보고 대화할 수 있는 나만의 동반자입니다."

Scene 2. 숫자를 표정으로 읽기 [0:20–0:50]
---------------------------------------
자동 조작: 메뉴 → 차량 상태 → Debugger의 배터리 15% → 창 축소 → 홈 표정 → 80% 회복.
화면: 정상 배터리 카드 → 낮아진 배터리와 경고 → 배고픈 표정 → 회복된 표정.
자막: "시뮬레이션: 배터리 15% → 80%"
내레이션:
"배터리가 부족해지면 차량 정보뿐 아니라 친구의 표정도 달라집니다.
 지금은 테스트 신호로 배터리 상태를 바꾸고 있습니다.
 숫자와 경고는 그대로 확인하면서, 캐릭터를 통해 변화도 쉽게 알아차릴 수 있습니다."
편집: 디버거 펼치기와 입력 과정은 2~3초만 남긴다. 표정 변화를 클로즈업한다.
선택 추가: 타이어 경고는 수동 리허설 후 별도 컷으로 찍는다. 기본 자동 실행에는 넣지 않는다.

Scene 3. 휴대폰으로 계정 연결 [0:50–1:15]
---------------------------------------
자동 조작: 설정 → 연결 안내 → QR로 연결하기 → 실제 승인 대기.
수동 조작: 스마트폰에서 실제 코드 입력/권한 승인.
화면: QR/기기 코드 → 승인 완료 → 계정 상태. 개인 계정명은 편집에서 가린다.
자막: "GitHub 기기 인증 · 휴대폰에서 승인"
내레이션:
"AI 대화는 GitHub 계정을 연결해 시작합니다.
 차량 화면에서 긴 비밀번호를 입력하는 대신, 휴대폰으로 QR을 열고 기기 연결을 승인합니다.
 계정 인증 후에는 Copilot을 이용할 수 있는지도 따로 확인합니다."
편집: 승인 대기 구간은 줄여도 된다. 실패를 성공으로 바꾸거나 가짜 계정 화면을 만들지 않는다.
이미 연결된 촬영의 대체 문장:
"미리 승인한 GitHub 계정이 연결되어 있습니다. 이제 Copilot 대화를 열어 보겠습니다."

Scene 4. 내 차 매뉴얼에 질문하기 [1:15–1:55]
------------------------------------------
자동 조작: 홈 → 대화하기 → Copilot 연결됨 확인 → 질문 입력 → 전송.
입력 질문(ADB 한글 입력 문제를 피하기 위한 영문):
"What is the recommended tire pressure for IONIQ 5? Use the manual and reply in Korean with sources."
화면용 질문 자막: "아이오닉 5 권장 타이어 공기압은?"
화면: 실제 답변 도착 → 근거 출처와 해당 조건을 충분히 보여준다.
자막: "2027 한국형 IONIQ 5 취급설명서 기반 · AI 답변과 출처 확인"
내레이션:
"권장 타이어 공기압을 물어보겠습니다.
 이번 데모에서는 앱에 담긴 아이오닉 5 취급설명서를 찾아, 답변과 출처를 함께 보여줍니다.
 긴 매뉴얼을 처음부터 넘기지 않고 필요한 내용을 찾아볼 수 있습니다."
주의: 답변을 미리 단정해 녹음하지 않는다. 실제 표시된 답변과 일치하도록 편집한다.
답변 대기 5초 정도는 남기고 나머지는 줄인다. 출처는 최소 5초 확보한다.
한글 입력 장면이 꼭 필요하면 --scene chat 대신 해당 컷을 직접 입력/전송해 녹화한다.

Scene 5. 작은 도전이 나만의 친구로 [1:55–2:35]
--------------------------------------------
자동 조작: Debugger에서 전체 조건 만족 → 퀘스트 → 놓지마 생명줄! → 보상 받기 → 확인.
           꾸미기 → 옷 → 선택 아이템 → 구매 확인 → 이 모습 적용 → 홈.
자막: "퀘스트 조건 시뮬레이션 · 보상 수령과 구매는 앱에서 처리"
내레이션:
"차량과 함께하는 작은 도전은 포인트로 이어집니다.
 여기서는 테스트 조건을 충족시킨 퀘스트의 보상을 받아보겠습니다.
 모은 포인트로 소품을 고르고 적용하면, 홈에서도 내가 꾸민 친구를 만날 수 있습니다."
편집: 포인트 증가, 구매 전 가격/잔액, 적용 후 모습을 차례로 보여준다.
디버거의 '일괄 지급'이나 '+' 버튼을 주행 보상 장면으로 사용하지 않는다.
이미 보유한 아이템이라면 "이미 모은 소품을 골라 적용해 보겠습니다"로 바꾼다.

Scene 6. 즐거움도 주차 중에 [2:35–3:00]
--------------------------------------
자동 조작: 시스템 홈 → 떠 있는 캐릭터 → TEST P → D → 퇴장 → 녹화 정지 대기.
화면: 바탕화면 캐릭터를 5초 이상 보여주고, 주차 해제 시 퇴장을 보여준다.
자막: "주차 상태 해제 시 상호작용 제한 · 캐릭터 퇴장"
      "에뮬레이터 테스트 · 실제 차량 런처 동작은 별도 검증 필요"
내레이션:
"허용한 화면에서는 앱 밖에서도 친구를 만날 수 있습니다.
 주차 상태가 해제되면 상호작용이 제한되고, 캐릭터도 화면에서 퇴장합니다.
 쉬는 시간에는 즐겁게, 운전할 때는 운전에 집중하도록. 지금까지 MobiMon이었습니다."
녹화 정지 후 Enter를 누르면 도구가 테스트 기어를 P로 돌린다.
Ctrl+C로 끝냈다면 TEST D → P 버튼으로 직접 복구한다.

재촬영과 중단 대응
-----------------
- 퀘스트/구매/장착은 저장된다. 재실행한다고 초기화되지 않는다.
  동일 퀘스트를 다시 찍으려면 촬영 전 Debugger의 '완료 이력 초기화'를 직접 사용한다.
  상점 Reset은 보유/착용 아이템을 바꾸므로 필요한 경우에만 직접 수행한다.
  자동 도구는 초기화 버튼, 직접 포인트 추가, 앱 데이터 삭제를 사용하지 않는다.
- 선택 아이템이 이미 착용 중이면 다른 아이템을 선택하거나 기본 장식을 직접 적용한 뒤 재촬영한다.
- 배터리는 마지막으로 성공한 입력값에 남는다. 중단 시 Debugger에서 회복시키고 P를 확인한다.
- 잘못된 화면/권한/잔액 부족이면 자동으로 성공 처리하지 않고 중단한다.
  문제를 해결한 뒤 --scene으로 필요한 장면부터 다시 찍는다.
- AI 연결 불가 시: 나머지 장면을 각각 촬영하고, AI는 '연동 준비 중'으로 표시한다.
  실제 연결/답변 성공을 촬영하지 못했다면 성공 내레이션을 사용하지 않는다.
- 오버레이가 나오지 않으면 권한/설정/P 상태를 확인한다. 해결되지 않으면 해당 장면을 빼고
  차량 상태 화면의 주차 제한 장면을 직접 촬영한다. OEM 검증 완료라고 표현하지 않는다.
- 도구는 녹화 파일을 만들지 않는다. 최종 영상 저장/잘라내기/자막은 Android Studio와 편집기에서 한다.
